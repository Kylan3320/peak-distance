# M11：多语言学习与本地 Markdown 学习库

多语言和共享学习库的行为规格。第 6 节列出待实现目标及验收条件。[ROADMAP](../ROADMAP.md)维护排期、已复现缺陷和待实机验证项。

## 1. 目标与范围

让用户在同一电脑的 Chrome、Edge 中学习多种语言：就地查词、句段翻译、YouTube 双语字幕、收藏、原句复习和再次遇见标记形成闭环；两浏览器连接同一学习文件夹，Obsidian 中修改的笔记和状态能读回。

- 基础查询默认免账户、免 Key，沿用现有免费在线渠道；没有词典时允许展示明确标注的译文，不承诺每个语言对都有完整词典字段。
- 用户主动打开“无词典结果时自动使用 AI”后，明确查词才允许词典未命中时调用当前 LLM。开关默认关闭。
- 每种源语言可设置一个理解语言，共用于词语解释、句段和字幕译文；显示语言独立，按后续界面语言规范执行。
- 一个生词本，按源语言隔离词条和学习状态，支持语言筛选；网页与视频共享记录。
- 文件夹可位于现有 Obsidian 仓库内。两浏览器分别授权同一目录，无额外常驻程序、云账户或 Obsidian 插件。
- 两浏览器可同时使用；切回浏览器或打开面板时更新即可，不要求跨应用逐字实时协作。
- 共享词汇、原句、字幕句子收藏、学习状态、个人笔记、语言偏好、完整聊天历史及其已提交材料／引用；接受少量辅助元数据。

产品范围见 [PRD](../PRD.md)，选区翻译与摘录收藏见[翻译学习规格](translation-learning.md)。

## 3. 多语言行为

### 3.1 首版范围与降级

首版目标清单：英语、中文（简体／繁体目标显示）、日语、韩语、法语、西班牙语、德语、葡萄牙语、意大利语、俄语、阿拉伯语、印地语、孟加拉语、印尼语、越南语、泰语、土耳其语、波兰语、荷兰语、波斯语。

语言标识、服务映射和能力状态集中在代码维护；保留实际字幕轨道标识与语言变体，按服务转换语言代码。

- 每个源语言都要能选区查询／翻译、保存原文和语境、复习、按语言标记；视频有原文字幕时还需支持轨道选择、分词查词和句子收藏。
- 无真实词典的语言仍可完成基础闭环，界面显示译文或 AI 释义，不伪造词性、词形、读音和例句来源。
- 清单外或暂不可识别的内容仍可选区和保存；明确显示待确认语言／当前能力缺项，不按英语处理。
- 服务失败与功能未实现分开记录；某语言的稳定失败不能用合成响应证明“已支持”。不静默缩减目标语言清单。

### 3.2 内容语言与理解语言

- 新安装默认理解语言为简体中文，可按源语言覆盖；不增加全局必选“当前学习语言”。
- 网页查词结合原句与局部语言线索。选区翻译的语言优先级见[翻译规格](translation-learning.md#4-请求语言与响应)。
- 视频以用户选中的原文字幕轨道为准。首次沿用当前可用轨道；没有当前轨道时选可用原文轨道并显示语言，同一语言优先人工字幕。允许手动换轨，不强制切英语，也不把平台翻译轨道当原文。
- 单个短词／专名无法确定时使用「待确认」身份，仍可收藏。句段可使用服务支持的语言自动检测。
- 切换理解语言影响新查询及当前可见译文；历史解释保留其语言和来源，不批量重译。源语言与理解语言相同时，不生成重复字幕译文，词典和学习操作仍可用。
- 独立问答使用发送时生效的显示语言，用户明确要求的回答语言优先；不由所附材料或理解语言覆盖。依据为后续界面语言规范。

### 3.3 查询路由与 AI 开关

| 结果／动作 | 开关关闭 | 开关开启且 AI 已配置 |
| --- | --- | --- |
| 主动查词，适用词典有结果 | 词典结果 | 词典结果 |
| 没有适用词典，或适用源均明确未命中 | 免费译文 | AI 释义；失败可回退免费译文 |
| 词典网络／限流／解析异常 | 标明故障，可尝试免费译文 | 同左，不把故障当作明确未命中 |
| 悬停预览、页面标记、词汇统计、预取 | 不调用 AI | 不调用 AI |
| 主动句段翻译、常规字幕模式 | 常规翻译链路 | 不受查词开关影响 |
| 点击解释语境，或已有明确 AI 翻译模式 | 沿用明确 AI 动作 | 同左 |

- 开关可以保存，但未配置 AI 时说明需要配置，当前查询继续免费路径；配置 Key 本身不打开开关。此调用授权保存在当前浏览器，不通过学习库替另一浏览器开启。
- 复用现有主／备用词典配置；不适用于语言对的源跳过。无需为每个语言增加一排供应商设置；能力映射由实现管理。
- 词典按源／目标语言对匹配；其它语言的词典内容不能冒充目标语言结果。本轮不增加二次翻译词典解释的链路。
- 缓存命中与词典查询顺序见[翻译学习规格](translation-learning.md#4-请求语言与响应)。
- 复用请求去重与取消；从悬停进入点击词卡最多触发一次允许的 AI 请求。关闭开关后取消对应未完成自动兜底，迟到结果不覆盖当前状态。
- 新增 AI 词义结果与词典、普通译文、AI 语境解释可区分；一般释义不能冒充当前原句的语境答案。
- 请求固定源语言、理解语言、原文／语境及 AI 配置快照；缓存和在途身份随这些输入区分，词典缓存不混入其它语言的同形词。
- 翻译请求保留原文大小写与内容，词条规范化不改写翻译输入。替换现有按英文字母占比判定翻译失败的规则；专名或同语输入保持原文不直接判为失败。AI 提示按实际源／目标语言组织，沿用现有供应商协议。

### 3.4 分词、字幕、标记与复习

- 网页和视频共用语言边界逻辑；优先验证浏览器内置分词能力是否足够，再针对实际失败补最小处理。保留拖选词组入口，不建立全语言形态学引擎。
- 保留重音、撇号、连字符和原始显示文本；不能统一去音调或按英语词尾合并。大小写／规范化按语言处理，土耳其语等用例应覆盖。
- 同形异语表达分别保存，词形关联限同一语言且有明确依据；词条稳定 ID 与显示文本／文件名分开。
- 页面标记依据局部语言，无法确定时宁可暂不自动标记；不能把英语已掌握状态套到其它语言同形词。人工选区查询仍可用。
- 原句复习、字幕词次、悬停查词和再次遇见标记采用一致边界。整句／长段落不因“没有空格”就被判定成单词；显式翻译入口适用于所有文字系统。
- 译文链路按目标语言寻找已有字幕，其次平台翻译，再免费逐句回退。沿用时间对齐、AP、暂停恢复、轨道切换取消与语境定位。
- 将面向用户的“英文／中文”固定文案改为实际语言或“原文／译文”；旧设置与已保存中文字幕按兼容迁移读取，不做简单字符串全局替换。
- 生词本初始显示全部语言，记住筛选；复习使用显式选择的单一语言，默认沿用当前单语言筛选。全部视图进入复习时让用户选语言；待确认记录作为独立集合可筛选和复习。

## 4. 本地学习库

### 4.1 连接与保存边界

- 未连接文件夹仍可使用全部学习功能，保持现有本机保存。设置提供“连接学习文件夹”；Chrome／Edge 分别选择同一目录并授权。
- 空目录初始化学习库；已有学习库读取库身份后连接，不覆盖。第一次连接将本机持久记录增量合并进去，重复连接不重复导入。
- 一个浏览器配置文件连接一个学习库。断开不删除文件，待办按库身份保留；连接另一目录时不自动搬入原库内容。
- 目录可以是 Obsidian 仓库中的专用子目录；只管理该范围内已识别的学习文档，忽略 Obsidian 配置、回收站和无关文件。
- 连接后，文件夹承载共享持久资料；IndexedDB 是运行副本、索引及待写入队列，不是另一套独立的冲突裁决来源。
- 收藏／状态等先事务性提交本机并排队写入。只有共享文件及必要元数据成功提交，才显示“已写入学习库”。未成功时显示“已保存在本机，待写入”。
- 打开面板、窗口重新获得焦点／可见以及相关写入前触发读取；更新已打开页面的词汇索引。对同一触发合并执行，只解析变化的受管文件，不在每次悬停扫描库。
- 关闭面板后网页收藏、后台完成的聊天也要能写入，或保留可恢复待办并在下一次活动时自动补写。运行上下文见 [ARCHITECTURE](../ARCHITECTURE.md)。

### 4.2 文件组织与最小格式

当前词语／句子集合组织、受管属性与迁移按 [学习库集合与同步](vault-collections-sync.md)。逐词／逐句散文件仅作为旧格式迁移输入；精确格式以 `lib/vault/format.ts`、`collectionFormat.ts` 和 `chatFormat.ts` 为准。对话仍每会话一份 Markdown，文件名使用可读标题加短 ID 并处理本机文件名限制；去重不依赖文件名。

- 正文保留解释语言、结果种类和来源，必要的关联 ID 可由辅助元数据承载。不要把完整数据库 JSON、嵌套属性或大量隐藏标记塞进每份正文。
- `.peak-distance` 保存格式版本、关联、必要修订、删除和冲突信息；不增加完整版本历史。
- 可恢复单位是整个学习文件夹，包括辅助目录；单独复制某篇 Markdown 可阅读，但不承诺完整恢复聊天关系。已确认同步的记录不能依赖某个浏览器私有数据才能恢复。
- `偏好.md` 保存默认理解语言及按源语言覆盖；缺失条目用默认值，设置页与文件双向生效。Key、AI 服务配置、调用开关、未发送草稿、当前窗口／标签页状态、缓存不写入共享库。
- 类型、序列化和校验规则集中在代码；库内附简短使用说明。

### 4.3 Obsidian 双向编辑

| 外部操作 | 扩展行为 |
| --- | --- |
| 修改词条 `status` 或“我的笔记” | 下次读取更新列表、详情、复习及页面标记；扩展也提供简单笔记编辑入口 |
| 给句子／对话补充个人笔记 | 读回笔记；不新增句子学习状态或改变历史消息 |
| 添加自定义属性／其它正文 | 保留原内容；不尝试给任意 Markdown 推断产品语义 |
| 文件改名或在库内移动 | 按稳定 ID 识别，更新关联链接，不重复导入 |
| 删除记录（集合内分节或独立文档） | 成功读取完整目录并排除同 ID 移动后记录删除；旧缓存不能复活记录 |
| 暂时写坏属性、重复 ID、修改历史消息／材料等受管内容 | 保留文件，定位该项问题；暂停该项写回，其它记录继续工作 |

在 Obsidian 编辑笔记和状态时，保留词条 ID、源语言和表达。状态值沿用 saved／learning／known。

写入只更新受管字段／块，保留用户内容与格式；无 ID 的普通笔记不自动导入。

### 4.4 合并与并发

合并依据上次共同内容、当前文件和本机修改。

| 变化 | 处理 |
| --- | --- |
| 两边追加不同语境／独立记录 | 合并保留；按稳定标识去重 |
| 笔记变化＋释义追加，或不同字段变化 | 自动合并 |
| 同一字段改成相同结果 | 视为一致 |
| 同一状态改成不同值，或同段笔记被双方修改 | 报告冲突并保留双方内容 |

删除与修改相撞的已知缺陷见 [ROADMAP](../ROADMAP.md#已复现缺陷)。跨程序写入边界见 [ARCHITECTURE](../ARCHITECTURE.md#多语言与本地学习库边界)。

### 4.5 完整聊天与材料

- 每条历史消息保留角色、文本、次序、时间、完成／停止／失败／中断状态；保留解释标记和现有可用来源信息。材料、引用段落、范围、视频位置与对应轮次共同保存。
- 完整历史是全部已持久化历史，不是请求模型时裁剪后的最近几轮。材料只保存当时实际捕获／提交的范围，不重新联网扩成全文。
- 对话 Markdown 提供顺序阅读和材料链接，个人笔记独立。材料快照不可变；2026-10-15 的可靠性修复在删除会话时清理该会话独占的材料，保留其它会话文件，不增加全库自动垃圾回收。
- 每轮生成归发起浏览器所有。本机按现有机制保存流式进度，文件按适当节奏写入，完成／停止／失败时尽快提交；另一浏览器不自动接管、重试或把外部生成状态改成中断。
- 文件写入尚未完成时，另一浏览器只能看到已写入部分；用来源／状态说明，不伪装实时同步。发起浏览器恢复后按自身请求情况处理中断。
- 共享历史经同步读回。生成期间远端提交新一轮的时序见 [ROADMAP 的问答同步缺陷](../ROADMAP.md#已复现缺陷)。
- 保留 M10 首次发送才持久化、临时输入关闭／切会话丢弃、模式与标签切换保留的规则。连接和刷新学习库不重建或覆盖当前未发送草稿。

## 5. 迁移与兼容

- 在原 IndexedDB 上增量升级；保留原有记录 ID／关联的可追溯映射和旧版本数据。首次写入学习库后重新读取并核对关联，再确认迁移完成，不通过清库简化实现。
- 有明确轨道语言或可核对词典证据的旧记录按证据归属。只有英文产品定位、ASCII 拼写、旧请求固定 en 等不足以证明原文语言；无法确定的放“待确认”，仍可查看／复习，不自动用于跨语言标记。
- 同一旧词条的语境若实际跨语言，按语境拆分并保留旧身份映射。迁移可继承旧状态以避免丢失用户操作，并标明待确认；新发生的跨语言状态互不联动。
- 两浏览器已有数据按语言身份、语境及稳定消息身份合并，重试迁移不增加副本。ID 相同但内容分歧按冲突处理，不把不同会话仅因标题相同就合并。
- 旧 Key、供应商配置、窗口行为、原文／中文历史结果保持可读。曾共享的记录修改目标语言后不重写历史。
- 旧版本持久化草稿保留本机兼容数据，不作为共享聊天历史或自动发送。
- 最低浏览器版本由清单配置定义，两浏览器共用构建。会话关闭语义见 [PRD](../PRD.md#问答与材料)。

## 6. 待实现目标

| 目标 | 验收条件 |
| --- | --- |
| 词条原文语言纠正 | 词卡手动选择只改变本次查询。纠正已保存词条时保留原句和笔记；遇到同语言同形词合并记录，复习选择有冲突时由用户决定。检测到 Markdown 中的身份字段被直接修改时，保留文件并提示从扩展内处理。 |
| 冲突版本选择 | 同字段冲突时可使用文件版本或本机版本，笔记可编辑合并。删除与修改相撞时可选择保留或删除。另一浏览器读回应采用同一决定。 |
| 分叉续聊 | 续问前读取共享新历史。两端从同一旧消息各自续问时，保存成两个可读会话，各自保留共同前缀、自己的后续消息、材料及来源。 |
