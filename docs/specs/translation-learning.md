# 选区翻译：浮窗、收藏与响应优化

## 1. 目标与执行边界

2026-10-22：用户确认以本方案为准。本文定义本次交付的行为与验收；实施状态见 [ROADMAP](../ROADMAP.md)，完成条件见第 7 节。

目标：选中内容后及时看到翻译、移开浮窗继续阅读、一键收藏到当前学习库，并能重新找到；查询缓存有期限、有容量上限，与收藏记录独立。

- 覆盖已有普通网页、X、YouTube 正文／字幕及固定／浮动侧栏内的选区翻译入口，共用一套行为。
- 沿用 Google 免 Key 翻译、有道／剑桥词典、现有学习库事务与同步、纸感界面及五语言文案。缓存未命中时的词典网络顺序、AI 授权边界与字幕播放规则不变；缓存命中规则按第 4 节。
- 翻译收藏作为独立知识点，写入当前连接的学习库根目录 `知识点.md`。不逐条选择子文件夹，不新增记录类别、顶层导航或同步引擎。
- 本文替代 [M8](m8-peak-distance-uiux.md) 与 [当前文章学习规格](current-content-learning.md)中“不增加段落收藏”的限制，仅开放用户主动收藏的选区翻译。AI 回答收藏的既有规则继续适用。
- 本文第 4 节替代 [M11](m11-multilingual-local-vault.md) 中“免费译文缓存不能绕过词典”及选区翻译仅将页面 `lang` 视为线索的约定：满足条件时直接复用译文缓存，选区元素继承的有效 `lang` 作为明确源语言。网页查词与标记的其他语言判断规则保持原有范围。
- 不增加服务供应商、Key、代理设置、离线模型、全文预翻译、自动 AI 请求、句子 SRS、通用调度框架或长期网络监控。输入范围与 `MAX_SELECTION_CHARS` 沿用现有约定。
- 本次实施不发布版本、不改版号；只更新直接受影响的规格状态、产品／设计约定和实现边界。

## 2. 翻译卡

### 2.1 布局与位置

- 点击入口后首个渲染帧即显示卡片和完整原文；读取设置、库归属及网络请求不阻塞挂载、拖动和关闭。
- 标题栏拖动，正文保持可选中和复制；按钮、链接、语言控件不触发拖动。标题栏有可访问名称，聚焦后方向键每次移动 16 CSS px；Esc 关闭。
- 沿用现有卡片宽度。首次定位优先选区下方，其次上方；都放不下时放在可见范围内。四边至少留 12 CSS px，卡片高度受可用视口约束，正文内部滚动，标题和底部操作保持可见。
- 译文到达、语言／状态文案变化、视口缩放／尺寸变化及全屏切换后重新约束边界。用户拖动后只做必要的边界修正，不重新吸附选区。
- 同一文档生命周期内重开时复用最后拖动位置；页面刷新或导航后重置。不持久化跨网站坐标，不增加尺寸调节功能。
- 标题栏提供「保持展开」，默认关闭。关闭时卡外点击继续原点击并关闭卡片；开启时卡外点击保留卡片。新翻译替换旧卡，Esc 依次收起已展开的下拉、次级区和卡片；显式关闭及页面导航仍关闭，下一张卡恢复默认。保持展开不改变请求或收藏归属。
- 默认阅读层只显示单行语言方向、次级原文、突出的译文；来源位于底部左侧。语言方向点击后展开本卡语言控件；重新翻译、保存位置与学习库管理入口在「更多」中。底部右侧相邻放置复制与收藏 SVG 图标按钮（34px 命中区），不使用文字按钮或大块主色；已收藏后以蓝色实心书签替换收藏按钮，点击查看收藏；复制成功显示勾选，保留本地化提示、可访问名称及就近错误反馈；失败就近显示重试。保持展开使用带可访问名称、提示和按下状态的图钉按钮。
- 来源标题单行省略，保留完整可访问文本及链接。沿用现有样式；新控件均可键盘操作，并接入五语言目录。

### 2.2 状态与异步生命周期

| 状态 | 可见内容与操作 |
| --- | --- |
| 设置／归属读取中 | 原文、加载状态；可拖动／关闭；收藏待归属确认后可用 |
| 翻译中 | 原文、语言方向、翻译状态；允许收藏原文，复制译文不可用 |
| 成功 | 原文、译文、Google 来源；底部相邻的收藏、复制图标（提示分别为「收藏翻译」「复制译文」），「重新翻译」收在更多中 |
| 首次失败 | 原文与对应错误；「收藏原文」「重试」，不显示伪译文 |
| 同一请求条件重新翻译 | 保留已有译文并标明更新中；失败后保留旧结果并明确更新失败 |
| 原文或语言方向改变 | 立即移除旧方向的译文／复制状态，按新身份更新收藏状态并启动新请求；不改写旧收藏 |

- 每次打开及每次重试／语言变更固定独立请求身份；设置、库归属、翻译及保存回执均检查该身份，旧流程不能挂载旧卡、取消新请求或更新新卡。
- 关闭未收藏的卡片取消其查询。已收藏／正在收藏的查询按第 3.3 节完成回填；关闭 UI 不删除已提交记录。
- 扩展上下文失效提示刷新页面恢复，不提供无法恢复的循环重试。普通服务失败保持现有手动重试，不叠加自动重试。
- 显式关闭恢复仍有效的触发点焦点；卡外关闭不抢回焦点。显示语言切换不重建卡片、不发翻译请求。

## 3. 收藏与学习库

### 3.1 内容及身份

- 原文、译文、源／目标语言、翻译服务、来源标题／链接和可用的位置元数据随记录独立保存；无译文也可保存原文。记录不得依赖查询缓存、当前页面 DOM 或聊天存活。
- 扩展现有知识点来源，明确区分 AI 回答与翻译摘录；不伪造 `chatId`／`messageId`。AI 回答仍按原回答身份去重。
- 默认标题取原文合并空白后的前 80 个 Unicode 字符；正文保留完整原文及当时可用的译文。保存后复用知识点标题／正文编辑器，不在首次收藏前强制弹编辑表单。
- 去重范围为同一学习库内的来源身份、位置、原文、请求源语言模式（自动或显式语言）及目标语言。原文只统一换行、NFC 和首尾空白，不折叠大小写、内部空白或标点。
- 网页沿用文章身份规范化；X 固定被选帖子的身份和链接，不用信息流地址代替；字幕带视频、轨道及起止位置，相同文字在不同字幕位置分别保存。只有字幕选区记为视频来源，YouTube 页面正文仍为网页来源。网页没有可靠位置时同源同文合并，不新增全文定位系统。
- 重复收藏返回已有记录，不覆盖编辑或新增副本；删除后再次主动收藏产生新记录身份。
- 收藏使用打开时固定的库归属。卡片仍开着时换库，旧卡不得写入新库；提示学习库已切换并要求重新打开。断开目录仍沿用既有库归属和待写入机制。

### 3.2 保存与查找

- 点击收藏后立即显示提交状态并防止重复提交；只有本机记录和待同步操作同事务提交成功后才显示已收藏。失败保留原文／译文和重试入口。
- 「更多」中显示当前目标文件夹名称；收藏按钮提示当前动作，保存结果仍在底部就近反馈。无连接时在更多中显示本机保存及连接入口；目录选择／重新授权复用扩展设置页，不从网页直接调用目录选择器。
- 区分「已保存在本机，待写入学习库」与「已写入学习库」。后者必须有该记录对应修订的成功写入回执；旧回执不能确认新修改。文件写入不阻塞译文显示。
- 收藏成功后提供「查看收藏」，在现有面板打开该记录，不关闭原网页。现有「生词本」的「词语／句子」旁增加「知识点」分类，展示活动库全部知识点，按创建时间倒序，复用展开、编辑和删除。该分类支持标题／正文搜索及源语言筛选，隐藏词汇专用复习按钮，不新增全局知识点复习入口。
- 网页／X 摘录同时出现在当前文章的知识点列表，并进入既有本篇知识点复习；视频摘录从全局知识点分类查看，来源链接回到已存播放位置。不扩展视频工作区的页签和复习模型。
- 「查看收藏」清除阻挡目标记录显示的搜索／语言筛选，展开目标行；若期间已删除或换库，明确提示，不能显示另一条记录冒充成功。
- 本机未连接时保存、首次连接导入、目录重新授权、Chrome／Edge 读回、编辑／删除传播及库切换均复用现有生命周期。缓存清除、过期和淘汰不得影响收藏。

### 3.3 查询中收藏

- 收藏原文后，本次在途翻译由后台关联保存记录；关闭卡片或承载页面后仍可完成回填。回填与待同步操作同事务提交。
- 仅回填原记录缺失的译文，且记录仍存在、属于原库、正文未被用户编辑、语言方向与保存快照一致。被同一查询重试／改向替代的响应不得回填；删除后重新收藏的新记录和用户编辑不能被旧请求覆盖。打开其他选区不改变原记录与其在途查询的关联。
- 切库后无法安全回填原库时跳过，保留已保存原文；不能写入当前新库。浏览器退出／后台意外终止后保留原文，不新增持久翻译任务队列或自动续跑。
- 翻译失败不撤销收藏。重新打开相同摘录并主动重试成功，可在上述条件满足时补齐原记录；已有译文或已编辑正文不自动更新。

### 3.4 数据兼容

- 复用知识点 store、活动库事务、待办、集合格式与三方合并；同时更新翻译来源的序列化、解析、恢复和删除路径。
- 旧 AI 知识点可读、可编辑、可同步；本次新增来源／字幕元数据不能被旧端当成损坏记录后删写。升级学习库格式版本，沿用现有旧端拒绝访问机制，不做双写兼容。
- 网页内容脚本只新增本功能需要的保存／查询回执入口；保留现有发送方校验，不放开知识点通用 CRUD 或凭据访问。

## 4. 请求、语言与响应

- 直接翻译始终跳过词典；查词默认网络顺序仍为首选词典 → 备用词典 → 原有兜底。AI 兜底的开关、配置及主动意图边界不变。
- 默认 AI 兜底关闭且未显式指定词典时，先查适用词典缓存，再查同条件的有效 Google 译文缓存；任一命中即返回，不先重复请求词典。用户显式选词典仍查询该词典，不能被已有译文短路。
- 词条匹配的规范化与翻译输入分离。直接翻译、查词翻译兜底均保留输入大小写、重音、标点和内部换行；不得把 `US policy` 发成 `us policy`。同输入、同语言条件复用同一翻译缓存与在途请求。
- 翻译卡提供源语言（含自动）与目标语言控件，仅影响本卡，不修改全局设置。源语言优先级：本卡手动选择 → 选区对应字幕轨道 → 选区元素继承的有效 `lang` → 自动。不把拉丁字母或纯汉字启发式判定当成已确认语言；快照须区分明确语言和启发式猜测。元素继承的语言若与解析目标为同一主语言，则本卡初始使用自动模式，避免仅凭整页元数据跳过翻译；字幕轨道与本卡手动选择保持优先。
- 已明确源语言时按其理解语言覆盖设置确定目标；自动模式使用默认理解语言，并在卡片显示实际方向。Google 的识别结果用于显示与保存，不触发第二次翻译；用户确认／纠正源语言时再应用对应覆盖。用户手动选择过目标后，本卡的源语言变化不覆盖该目标。不另发语言检测请求或调用 AI。
- 保存的源语言使用已明确／检测到的有效语言，仍不确定用 `und`；去重中的自动模式身份不因检测结果改变。先收藏原文后可随译文补齐识别语言；已收藏记录仍绑定原请求方向，不被后续语言控件操作改写。
- 同一服务请求沿用现有超时；相同在途查询合并，消费者分别取消。结果到达后更新内存并立即返回 UI，不等待查询缓存持久化或学习库文件同步；收藏本机提交仍需等待事务成功。
- 「重新翻译」／失败重试绕过本次查询的旧缓存；被替换请求不能把旧结果重新写回。成功后替换该缓存，失败不把错误文本缓存为译文。

## 5. 查询缓存与连接实验

### 5.1 固定缓存规则

| 项目 | 规则 |
| --- | --- |
| 持久化范围 | 成功的普通词典及 Google 文本翻译结果，跨浏览器重启保留；字幕快照／AI 结果保持既有会话缓存，不扩大持久化范围 |
| 有效期 | 普通词典／文本翻译从成功取得结果起 30 天；`now >= expiresAt` 即失效，命中不续期；重新请求成功才重置有效期 |
| 容量 | 沿用 `cacheLimit`：默认 200、范围 20–500；所有查询缓存类别合计不超过该条数及 2,000,000 UTF-8 字节，内存镜像不重复计数；单条超限可展示但不缓存 |
| 淘汰 | 先删过期项，再按最近使用时间从旧到新淘汰，直到同时满足条数和字节上限；同时间按写入时间、缓存键稳定排序 |
| 清理时机 | 缓存初始化、读取、写入、上限变更时清理并安排落盘；不设定时清理／后台保活。扩展未运行时不要求主动清盘，容量上限始终有界 |
| 命中记录 | 最近使用时间在内存更新，随下一次缓存变更落盘；不为每次命中单独写存储。重启后允许近期使用排序近似，有效期必须精确 |
| 不缓存 | 网络错误、限流、取消、空响应、解析失败及词典未命中；过期结果不作为断网兜底返回 |
| 缓存身份 | 普通查询使用服务、结果类别、实际源语言模式／目标语言、实际输入及结果格式版本；不含库目录、聊天、API Key。目标变化不复用旧方向结果；AI／字幕既有作用域规则保持不变 |
| 旧缓存 | 旧普通查询缓存可直接丢弃重建，不迁移无可靠有效期的结果；收藏、字幕／AI 会话数据不随之清空 |
| 手动清除 | 在现有查词设置内提供「清除查询缓存」，清除普通词典／文本翻译的内存与持久缓存；清除前在途请求可完成显示，但不能把旧代次结果重新缓存。收藏及其他设置不受影响 |
| 存储失败 | 已获得的结果仍可显示；记录现有诊断，不误报收藏失败。下一次缓存变更可重试持久化，不无限重试或新建恢复队列 |

缓存只留在当前浏览器，不写入学习文件夹。复用 `lib/onlineCache.ts` 的入口与请求合并，避免再建独立路由缓存。设置名称与说明更新为实际查询缓存含义，说明 30 天自动过期和容量限制；不增加 TTL 配置、统计面板或缓存管理页面。

### 5.2 Google 连接预热的保留条件

此项先验证后决定是否进入运行代码，不以独立页面或 Node 探针代替扩展后台证据。

- 候选行为固定为：本浏览器会话首次出现可翻译选区入口时，由实际执行翻译的扩展后台向现有 Google 翻译端点发一个无选区文本、无凭据的 HEAD 请求，超时 3 秒。不等待预热完成才翻译，不重试、不周期保活；最多一次，不能因 worker 重启重复触发。
- 在生产构建的扩展后台做 3 组冷启动配对测量：每组使用独立测试浏览器上下文；基线／候选均在入口出现 1 秒后点击翻译，禁用应用缓存与 HTTP 缓存，使用相同公开样例、语言方向和网络。测量点击到有效译文、实际请求数及可取得的连接／首字节耗时。
- 仅当 3 组均成功、点击到结果的中位数同时改善至少 20% 和 200ms、且证明正式请求复用了预热连接时保留候选行为。否则不加入运行代码，也不更换服务或增加其他预热方案。
- 无法验证连接复用或真实网络受阻时记录未验收结论，省略预热实现；其他必做项继续完成。不得宣称保证首次翻译秒开。

### 8.5 Google 限流修复与浏览器内置翻译实测（2026-10-24）

真实 Google 请求重定向至 `/sorry/index` 并返回 429，Chrome 普通导航显示异常流量验证页；同环境的有道返回正常词条。0.6.9 原字幕处理在受控的六次 429 下继续请求六句，最终返回 `ok:true, translations:[]`。当前修复仍保留 Google 常规渠道，不自动切换 AI，也不提前接入尚未完成验证的原生渠道。

修复将访问限制放在现有常规翻译模块：网页、查词兜底及字幕共用请求入口，已排队的请求先读取上一请求结果再决定是否访问 Google；429／403 及已知 Google 验证页触发 session 冷却，尊重 `Retry-After`，缺省使用实现中的默认时间。成功缓存继续可用，主动刷新不越过限制。503 保留 HTTP 故障身份。字幕遇到渠道故障停止剩余请求，保留已成功的句子和原始 ID；全部失败返回失败原因、HTTP 状态和重试时间。冷却状态落盘失败有诊断，内存保护立即生效，写入延迟不阻塞错误反馈。同一结果约束的复核还发现 AI 字幕全空／仅超出输入范围的响应会报告成功，已在解析和批次边界修正，并使旧无效批次缓存失效；验证使用受控响应，没有真实 AI 请求。

- 取消返回失败／aborted，关闭进行中的翻译卡后重新打开新文本，旧结果不覆盖新卡。
- 译文仍未完成时收藏、关闭，后台完成并回填同一记录，来源为内置翻译。
- 字幕保留输入 ID；关闭阅读页并主动销毁隐藏文档后，在浏览器离线模拟下重建、翻译未缓存的新句子。
- 整个内置流程没有 Google 翻译或 AI 请求；译文保持 14px。

旧 Chrome 探针配置仍出现“服务数量限制”提示；检查其本地测试目录发现翻译运行库目录缺失、登记路径为相对路径，干净配置正常下载运行库后通过。未修改用户配置，也未把浏览器提示直接认定为扩展泄漏；该异常保留为环境边界。这里只证明上述版本和英中用例的实际结果，不代表所有设备、语言、长文质量或长期压力均已验证。

可重复入口：`npx tsx tools/native-translation-check.ts`（会话释放、在途／排队取消、换行、识别、准备失败与来源往返）；`node tools/native-translation-runtime-check.mjs`（两款真实浏览器，支持 `--browser=chrome`／`--browser=edge`）。后者恢复 Playwright 默认关闭的 Translate、OptimizationHints 和组件网络行为，通过官方 DevTools 扩展安装接口安装当前构建；只在探针目录的隔离配置中重装测试扩展，使用浏览器沙盒，未强开实验 AI 特性。受控网页仅提供测试选文，译文来自真实模型。结果留在 `.upstream/native-translation-probe/integration-results.json` 及分浏览器记录。类型、构建、上述定向检查及既有翻译可靠性／缓存检查通过；未运行全量回归，尚未发布。
