## 2. 用户链路与行为

### 2.1 当前文章

- 顶部显示文章标题与域名来源，完整 URL 保留在外链与提示中；最近选区位于来源下方，预览可展开完整选文。下设带当前范围计数的「生词／知识点」切换；「复习本篇」为 SVG 入口，仅在当前类别及语言范围有可复习记录时显示。筛选无结果与未收藏空态分别说明，前者提供清除筛选。当前内容跟随活动页面，AI 会话继续独立。
- 生词按语言作用域词条聚合，一行一个表达，数量按不同词条计；覆盖 saved／learning／known。默认按本文最新保存上下文的时间倒序，预览用本文最新原句及对应解释；没有语境解释时，直接展示同一上下文已保存的一般释义参考并标明类型与来源，均无结果才显示缺失。词典参考采用用户已选义项。行内展开本文其他上下文、详情和个人笔记。其他文章语境在全局词条详情查看。
- 收藏成功后刷新本文列表。重复收藏保持现有去重与状态规则，新增语境不自动改变 known；不虚构旧数据中没有保存的收藏次数或时间。
- 支持查询未完成时先收藏；关闭已收藏或正在收藏的词卡不取消本次基础查询，结果到达后回填原保存上下文。未收藏的词卡关闭仍取消查询，主动语境解释继续沿用关闭取消规则。实际服务失败仍保留原文，不编造释义。
- 原句可返回原文；定位反馈就近显示，4 秒后消失，顶部定位反馈也在离开视图时清除。定位失败仍能查看已保存原句和来源，不伪造成功。历史记录从现有上下文 URL 派生文章身份，不要求重新收藏。
- 最近选区继续作为临时查词／翻译区域，不独占文章学习视图；无选区也能查看本文记录。无记录时说明保存入口；不支持或不能识别来源时说明范围，不拿上篇内容冒充当前页。
- 知识点列表按保存时间倒序展示标题与来源，行内查看正文、已存引用，支持修改标题／正文和删除。保存与删除反馈就近显示，失败保留可重试内容。

### 2.2 本篇复习

- 点击「复习本篇」只练当前类别，不默认混合词汇与知识点。
- 词汇沿用原句练习，默认 saved／learning，每词一道，取本文最新已保存上下文。原句、语境释义必须来自同一上下文；没有语境解释时可展示同一上下文已保存的一般释义参考，保持类型和来源，不借其他文章的解释；均未保存才显示缺失。
- 来源与语言取交集。沿用 M11：词汇复习使用显式选择的单一语言，当前单语言筛选直接沿用；全部语言进入时先选择一种；待确认语言作为独立集合，不混入其他语言。知识点保持启动入口的来源及已有语言筛选，不新增语言识别或评分模型。
- 启动时固定类别、来源、语言与返回目标。队列刷新、状态变更、再来一轮、窗口级恢复及固定／浮动移交都使用同一范围；切浏览器标签页不改变本轮。队列重建可反映范围内新增／修改／删除，不能回退到全库。
- 词汇的单词与释义分别点击揭示，任一操作不自动展示另一项，也不自动标记 known。知识点先显示保存的问题／标题，揭示后显示保存正文与必要引文，不增加掌握度。
- 两类复习均可在未揭示时前后切题、按序号跳题或打乱本轮队列；切题重置揭示状态。队列顺序、当前题及各自揭示状态随窗口恢复和模式移交保留；刷新保留现有顺序并追加范围内新记录，不扩大来源或语言。
- 结束或退出返回启动入口：全局生词本进入则返回生词本；本篇进入则返回启动文章及原类别，即使活动页已切换也不显示成新文章。离开该返回视图后，普通「当前内容」恢复跟随活动页。
- 查看、保存已有回答、编辑及复习均不触发新的 AI 请求。

### 2.3 保存独立知识点

- 仅对有可靠文章材料关联、正文非空、状态为已完成或已停止的 AI 回答提供「保存知识点」。生成中、失败／中断和缺可靠关联的回答不自动归入本文。
- 初始问题／标题为同轮用户问题，正文为该回答；保存前可编辑，保存后可修改标题与正文。取消编辑不生成记录。
- 来源取该回答同轮提问实际绑定的不可变材料快照；通过轮次及快照关联确定，不使用保存时活动页、聊天最新来源或文本猜测。切到 B 页面后保存 A 的回答，仍归属 A。
- 独立保存稳定 ID、标题、正文、可展示的来源信息、必要引用原文副本及其可识别定位信息。只复制可识别的必要引用块，不默认复制整篇材料／聊天；无可识别引用时保留正文和来源，不编造引文或定位。聊天／消息 ID 仅用于追溯及判重，读取不能依赖聊天文件。
- 同一库内同一回答重复保存返回已有知识点，不覆盖用户编辑；不同回答即使问题相同也不合并。独立删除后再主动保存原回答生成新记录，不恢复旧删除身份。
- 删除聊天及独占材料不级联删除知识点或其引用副本；删除知识点只删除该独立记录。原「保留解释」仍是会话内回答标记，不自动转为知识点，不自动迁移全部旧标记。

## 3. 数据归属与生命周期合同

### 来源与范围

文章身份沿用 `shared/chat.ts` 的 `normalizeArticleUrl()`／`sourceKeyOf()`，保留查询参数、按现规则处理文本定位／段落锚点和 hash 路由；原始 URL 另保留供回跳。不要另造一套去参数规则。旧词汇从 `ContextRecord` 派生来源，无可靠匹配的不强行归入本文。X 继续以目标帖子身份处理，不把信息流当成一篇文章。

列表查询、预览、计数与复习必须共同筛选上下文，再聚合词条；仅筛中词条后使用其全局最新上下文不满足合同。视频已保存词汇进入复习时复用同一范围机制，固定 videoId 及已选语言，保留原有词语／句子和轨道行为，不新增句子 SRS。

### 本机与学习库

- 知识点保存／修改／删除与待同步操作同事务提交，沿用活动库归属、修订确认、读回和失败反馈。未连接文件夹仍可使用；未落盘只显示本机已保存、待写入，不能提前宣称已同步。
- 沿用集合模式新增 `知识点.md`，稳定 ID 分节，必要恢复信息复用 `.peak-distance/`；正文、来源与引文副本必须随库完整恢复。不能只写聊天 ID 或指向可随聊天删除的材料文件。
- 本机未连库时的知识点在首次连接时进入既有导入／补队列流程；另一浏览器读回能查看、修改、复习。外部 Markdown 修改按既有字段合并合同处理；不同字段可合并，同字段分歧保留双方并报告，不按时间强行胜出。
- 独立删除进入既有删除传播与共同快照机制；旧运行副本、旧待办不应复活已删除身份。换库时归存／恢复知识点、待办、快照、冲突与判重信息，断开仍保留原库归属。
- 保留旧词汇、句子、聊天与库文件；增量升级不清库。共享新记录需参与同步的两端均更新到实现本 spec 的版本；不承诺旧版识别知识点。实施时依据实际序列化确定格式升级或拒绝策略，确保不支持新格式的一端不会静默删写未知记录；不为旧版构建双写兼容引擎。
- 保持现有权限、worker 串行、写前／写后校验与冲突边界，不把它描述为跨程序互斥。不扩大已有未实测原生目录并发保证。

### 6.3 审查发现的三项接续修复（2026-10-17）

- **字幕语言缓存**：旧构建在理解语言由中文改法语后仍接受原中文平台响应，并按新设置生成法语缓存键。现复用取消代次使旧翻译失效、清除当前译文并重新调度；平台请求固定启动时的目标及缓存键。专用生产内容脚本检查覆盖旧响应拒绝、新语言重取、源语言覆盖与正确缓存恢复。
- **知识点正文分隔**：旧集合解析先全局切分记录标记，正文中的 HTML 示例会被误认为新记录。现先识别成对正文包络，仅在其外切分集合；含受管标记的新正文采用稳定且不与正文冲突的成对标识。保留普通旧文件、旧正文中的记录分隔符及可确定的结束标记示例；覆盖多记录、正文 YAML、重复序列化稳定及损坏／孤儿记录拒绝。旧无标识包络若混入无法区分的同名正文／记录边界，仍报告格式错误，不猜测合并或当空库覆盖。
- **全局词卡跨库**：用生产扩展、两个真实窗口、IndexedDB／OPFS 库及延迟列表响应复现：A 卡片在切换到同名词条的 B 库后，状态、笔记、删除及词形移除均会改到 B。现四类操作绑定读取时的库身份，在数据库同一写事务内核对；列表代次拒绝迟到旧响应。检查同时覆盖 `null` 本机归属不能写入已连接库、返回 A 后正常操作，以及再次读 B 内容不变。

知识点纯逻辑往返与旧格式检查已接入既有 `regress`；`tools/youtube-translation-language-check.mjs`、`tools/vocab-ownership-check.mjs` 接入 `check-reliability`。本阶段词形正向检查当时仅验证当前库事务成功提交及旧库操作拒绝，发现同步并集可补回已移除词形；后续修复及加强验证见 6.4。本轮 `typecheck`、`build`、`regress`、`check-reliability` 最终均通过；后者包含生产构建的字幕／双窗口词卡检查及既有双浏览器同步回归。受控字幕响应、OPFS 与临时磁盘目录不替代登录态 YouTube、用户原生目录选择授权及跨程序并发实机验证。

### 6.4 词形移除与新增的三方合并（2026-10-17）

根因是 `mergeVocabRecord()` 的词形合并始终取本机与文件并集，未使用已存在的共同快照。离线检查及 Chrome／Edge 同步均复现：本机移除成功后，文件中的旧词形重新写回。

现仅调整既有词形合并函数及其基准参数：基准中已有的词形，任一端移除后不再补回；基准中没有的词形保留双方新增，维持本机优先的列表顺序。无共同快照时保留双方值，不根据缺失推断移除。发布与读回使用同一规则，不增加数据库字段、墓碑或同步流程。

验证通过：

- `tools/m11-vault-format-check.ts` 增加单边移除、双方移除不同词形、移除与双方新增、无基准及同步移除后主动重新新增等样例，已接入 `npm run regress`。
- `tools/vault-sync-check.mjs` 使用真实 Chrome／Edge 独立 IndexedDB 与共享临时磁盘目录，验证双向移除及清空、移除旧词形同时保留两端新增、两种先后发布顺序、双方与共享文件一致，以及重复同步不补回。既有同步回归全部通过。
- 生产构建的 `tools/vocab-ownership-check.mjs` 恢复同步完成后的词形为空断言，保留跨库拒绝及返回原库正常操作的验证；`npm run typecheck`、`npm run build`、`npm run regress` 均通过。原生目录实机边界沿用 6.3。
