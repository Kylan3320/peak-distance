# 问答发送与工作区恢复修复

日期：2026-10-13。范围：用户反馈的回车发送、首问后仍显示欢迎页、移除选区失败、历史无法打开。

本文按阶段保留取证和验证结果。“未发布”“重载尚未确认”描述该阶段时点；后续上边缘调节、安装重载与最终验收见 [审查及修复](code-quality-review-20261013.md)，正式发布见 [ROADMAP](../ROADMAP.md)。末节的原生右下角调节已由上边缘调节替代。

## 成功标准

- Enter 发送、Shift+Enter 换行，保留 Ctrl/⌘+Enter；输入法确认候选不发送。
- 首次发送提交后显示问题及回答占位，流式正文和终态更新，清除本次已发送输入。
- 移除材料保留下一问草稿，后续请求不再携带材料；已发送消息的原文引用仍能读取。
- 历史会话可打开并在原线程续聊，不新增重复会话。

## 取证与根因

- 取证时 Chrome 加载目录为 `/Users/boohee/Downloads/peak-distance-0.6.5-chrome`；修复前的 background 和 sidepanel 构建与仓库源码生成物一致，排除安装包与源码不同步。实机通过原生 UI 点击历史行后没有界面变化。
- 旧输入框只在 Ctrl/⌘+Enter 时调用发送，普通 Enter 使用 textarea 的默认换行行为；这是旧交互定义。
- `main.ts` 的启动流程在 `restoreChat()` 后才提交 `ready`。启动期间的 `visibilitychange` 会调用 `setChatActive(false)`；若面板重新可见但尚未 ready，`activePanel && ready` 仍为 false。随后 boot 只恢复主面板可交互，未恢复聊天模块活动状态。
- 因此主面板允许点击发送，而 `acceptRecord()`、轮询和草稿保存认为聊天模块不活动。端口发送及生成状态提示仍可运行，后台提交成功、界面却保留旧记录；欢迎标题和选区继续显示。
- 历史选择可改变后台编辑身份，但界面仍拒绝采纳；随后移除请求携带旧 chatId/editId，被后台按 `stale-edit` 拒绝。这些症状属于同一个活动状态失配，不能通过清空材料或强制改消息 DOM 解决。
- 确定性复现：预附加选区，在第一次附件渲染与启动就绪之间注入一次隐藏／显示切换。旧构建提交后仍显示欢迎页；在同一时序下，新构建显示完整问答，并可移除和续聊。`tools/check-chat-interactions.mjs` 指向旧安装包备份时会在首问展示断言处失败。

## 修复

- 初始化／模式恢复尚未就绪时，可见性事件不打断记录恢复；就绪时根据面板归属和当前文档可见性统一同步聊天活动状态。就绪后的隐藏／显示继续保存草稿、暂停和恢复聊天更新。
- 所有发送入口共用 `doSend()`；键盘与按钮使用同一发送逻辑，生成中阻止重复提交。
- 非组合输入状态的 Enter 发送；Shift+Enter 保留换行，Alt+Enter 保留原生行为；`isComposing` 和 Chromium 的组合输入 keyCode 229 不触发发送。提示和按钮标题同步五语言。
- 材料继续保留供追问；发送后清除的是本次问题和焦点，欢迎空态由真实消息记录决定。

## 追加：输入区高度

- 原输入框默认三行，并受到普通／矮窗口的最小高度限制。虽然启用了原生竖向 resize，向下压缩时仍会被最小高度拦住。
- 默认改为单行，允许通过右下角原生手柄拉大和缩回；高度上限随视口调整。沿用现有输入、换行与发送逻辑，设计约定更新于 `design.md`。
